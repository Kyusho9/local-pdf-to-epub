## 安装与资源准备

从 [最新 Release](https://github.com/Kyusho9/local-pdf-to-epub/releases/latest) 选择应用包，并下载 `LocalPDFtoEPUB-ocr-resources.zip`。

| 文件 | 用途 |
| --- | --- |
| `LocalPDFtoEPUB-0.1.6-windows-x64.zip` | Windows 64 位应用 |
| `LocalPDFtoEPUB-0.1.6-macos-arm64.zip` | Apple Silicon Mac 应用，不能用于 Intel Mac |
| `LocalPDFtoEPUB-ocr-resources.zip` | 两平台共用的本地 OCR 模型 |
| `LocalPDFtoEPUB-0.1.6-source.zip` | 项目源码、构建配置及 OpenCV/Vivliostyle 对应源码，供开发者使用 |
| `LocalPDFtoEPUB-0.1.6-third-party-sources.zip` | Qt、GEOS、FFmpeg 等对应源码与替换说明 |
| `SHA256SUMS.txt` | Release 附件的完整性校验值 |

解压应用后，Windows 双击完整目录中的 `Start-LocalPDFtoEPUB.cmd`；Mac 打开 `.app`。不要只复制 EXE。应用包含 Python、Qt 等运行时，普通用户无需安装 Python、Node 或配置命令行。Windows 需预先安装 Microsoft Visual C++ v14 x64 运行库（14.44.35229 或更新），从[微软官方下载页](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist)取得并运行安装器即可，无需安装 Visual Studio。断网电脑可复制微软官方安装器后自行安装。启动脚本只检查已安装的系统库，并为 Shapely 准备一份应用私有副本，不下载或安装系统组件。

在「资源与设置」选择资源目录并导入 OCR ZIP；使用 GPU 时另导入已准备的对应运行包。也可以主动点击联网下载。导入会检查版本、文件路径和 SHA-256。将应用与资源 ZIP 复制到目标电脑即可离线准备，目标电脑不必联网。

本次公开 Release 不附带包含 VC DLL 的 DirectML / CUDA 整合 ZIP。加速功能保留；已有匹配版本的本地运行包可继续使用，也可在应用中主动从固定官方来源下载准备。第三方组件的使用与转交须遵循其条款，不能把个人安装许可视为公开再分发许可。

Windows 新任务默认尝试 DirectML，可选择 CPU 或 NVIDIA CUDA；缺包或设备失败时默认明确回退 CPU。Mac 使用 CPU。旧任务未记录设备时按 CPU 恢复，已有 OCR 缓存保留其真实执行记录。驱动由操作系统提供。更多说明见 [离线资源](OFFLINE_RESOURCES.md)、[GPU 运行包](GPU_RUNTIME.md) 和 [平台要求](PLATFORMS.md)。

当前应用未使用 Windows 商业代码签名或 Apple Developer ID 公证，下载后可能出现系统信任提示。请从项目发布页取得文件；不要关闭整个系统的安全机制。

## 转换与校对

1. 选择或拖入 PDF，设置书名、作者、输出位置和基本样式。加密 PDF 需要正确密码。
2. 点击转换，查看当前阶段与页数。可靠文字层优先提取，扫描区域使用本地 OCR；高级选项可强制 OCR。
3. 在「校对与导出」对照原页查看正文、图片及疑点，修改标题、段落或手动合并需要连接的段落。
4. 保存并重新导出。输出同时生成质量报告；格式校验通过不代表文字准确。

存在失败、排除或未处理页时，只有明确允许部分结果才能导出，报告会列出缺页。耗时任务可取消后继续；失败页可以单独重试。

## 旧任务与重新整理版面

通过「重新打开任务」选择任务目录，原始识别、自动稿和人工修订都会保留。

若旧版结果中段落过碎或扫描图片遗漏，选择对应页，或选择「全部页面」，点击 **「重新整理版面（复用识别）」**。它复用已有文字行，重新整理段落和图片，不加载 OCR / GPU 模型。人工修订仅在原文字和来源能可靠匹配时迁移；无法匹配的修订保留并提示冲突。

只修改字号、行距或页边保留开关时，直接保存并重新导出即可。请保留完整任务目录，尤其是 `source.pdf`、`raw/`、`pages/`、`assets/` 和 `edits.json`，以便回查与恢复。任务包含原文件和提取内容，应按普通本地文档妥善保存。

## 页眉、页脚与原页码

勾选「保留页眉、页脚和原页码（兼容阅读器）」后，通过软件中的 **「兼容阅读器打开」** 查看。阅读时保持应用运行，在本机浏览器中用 A+ / A− 调整字号。阅读器资源随应用提供，只连接 `127.0.0.1` 的本机服务，不需要外网或账号。

每个阅读页采用其**起始正文来源**的原页眉、页脚和原页码。字号变化后，一个原页可能铺成几个阅读页，一个阅读页也可能容纳几个原页；重排不会固定 PDF 的原分页。原页信息不另做正文附录。

取消勾选会省略输出中已识别的页边文字和号码；原稿、来源与修订仍保存在任务里。归属不确定的文字会保留待核对。图片中已烧录的文字随原图保留，不自动擦除或重画。

扫描页码优先从原页像素识别。只有邻页证据足够时才建议补写缺口，必须经用户确认；确认值明确记录为人工推算，启用页边后显示在页脚。可以撤销；来源冲突时不会继续显示。人工跨页改文导致来源边界不可靠时，该块页边会清空并报告，下一可靠来源恢复。

实际已验证的页边阅读方式是应用提供的 Vivliostyle 本地阅读器与 Edge / Chromium。其他阅读器可能忽略这些页边信息；此前 Flow、Apple Books 的测试未通过完整页边对应验证。详细兼容性记录见 [0.1.4](RELEASE_0.1.4.md)。

## 支持范围与质量限制

主要支持普通横排中文及中英混排、文字与扫描混合、基础双栏、插图、普通表格和书签目录。复杂公式可保留原区域图片；竖排、手写、复杂表格、跨栏及低清晰度扫描仍需人工核对。

封面和插图使用原页图像；烧录在图内的文字也会保留。小型行内图标的位置由几何信息估计，相邻 OCR 字符不会擅自改写，仍需核对。当前只对可靠的简单数字脚注建立链接，没有新增复杂注解关系重建，也不提供自选封面或完整电子书排版编辑器。

正文默认忠实提取，不自动润色、翻译、总结或凭常识补写。OCR 分数来自引擎，启发式疑点单独记录，不把它们当作全文准确率。更多限制见 [后续任务](ROADMAP.md)，实测范围见 [版本记录](RELEASE_0.1.6.md)。

EPUBCheck 是可选额外校验组件，需要本地 Java 与 EPUBCheck；主应用尚未捆绑它们。未配置时会明确报告未运行，不会把内置结构检查称为 EPUBCheck 通过。
