# 0.1.6 — 扫描图片、段落与网址页脚

状态：首轮两平台构建与实际 GUI 流程完成，但检查 Windows 记录时发现验收快照的路径分隔符导致空字典。该验收代码已修正，并强制要求所选页的原始缓存存在；首轮候选与原始记录保留，不作为最终缓存不变的证据。两平台正在用修复后的同一源码重新测试、构建和验收，以下首轮包摘要会在最终结果确认后替换。转换算法未因这项验收修复改变，源码与下载资源尚未发布。

## 本轮范围

- 保留扫描封面和正文中的小图形，使用 PDF 原像素裁切，并记录来源。已烧录在封面或插图中的文字属于图像，不涂抹、不生成替代图片。圆形注释标记作为原图保留，不据外观擅自建立注释链接；邻近 OCR 可能重复识别其字符，仍需报告和校对。
- 段落整理使用 OCR 四角坐标测量真实字高和倾斜方向，再结合行距、缩进、对齐及标点判断连接。源坐标与逐行文本保留，几何分析不改写文字。跨页合并只采用充分的版面证据，不保证复杂扫描的全部段落自动恢复。
- 重复推广网址按页脚识别。需要至少三页提供独立底边小字、相同网址及相近位置的证据；网址路径不同、正文网址、编号脚注、缺乏几何信息或来源混合时保持保守。没有针对某本书或某个网站的删除名单。
- 从任务已有的原始识别结果重新整理版面，不重新加载 OCR / GPU 模型。重新整理保留原始缓存，人工修订按来源核对；无法可靠匹配时保留为冲突，不静默覆盖。

## 已验证的局部结果

- 页脚规则的六项新合成几何回归及一项既有边缘规则回归通过，共 7 项。覆盖旧版误标的脚注 / 标题、倾斜长行的真实字高、协议 OCR 变体、至少三页证据门槛，以及合法网址、人工修改、缺失和异常坐标等反例。这些测试不冒充真实 OCR 准确率。
- 对本地已有识别缓存进行了只读复核：重复网址页脚在关闭保留选项时从导出正文省略，开启时进入运行页脚计划；原始识别和页面缓存的摘要、修改时间保持不变。新段落来源中的多边形坐标也已交叉验证。用户材料及其提取内容仅保存在本机私有目录，不收入源码、测试样本或公开仓库。
- 公开发布准备脚本只选择源码、锁定依赖、对应第三方源码和自制样本；不选入任何本机验收目录。离线源码归档显式拒绝私有目录，即使额外指定该路径也不能收入。公开仓库 [Kyusho9/local-pdf-to-epub](https://github.com/Kyusho9/local-pdf-to-epub) 已创建，源码和资源将在本轮验收完成后发布。

## 最终源码与发布包验收

- Mac：完整工程测试 **128 项通过，50.33 秒**，测试期间源码摘要不变。原生 Cocoa 冻结 GUI 和后台进程在内核拒绝全部网络条件下通过混合文档转换、取消恢复、人工修订、页边开关、页码确认 / 撤销，以及选页重新整理。重整期间原始 OCR 摘要与修改时间、未选页缓存不变，人工修订保留。五个实际产物通过 EPUBCheck 5.4.0，零错误、零警告；归档解压、严格 ad-hoc 签名及清洁环境启动检查通过。
- Windows：完整工程测试 **127 项通过、1 项跳过，194.72 秒**。跳过的 `test_standalone_worker_rejects_other_platform_without_cloud` 专门检查非 Windows 平台拒绝运行 Windows worker，不适用于本机；实际 GPU 协议通过目标平台验收检查。新版独立解包后的 686 文件与 ZIP 全部一致，旧 0.1.5 同样 686 文件保持逐字节一致。清洁 PATH / ASCII 环境的冻结 CLI 启动通过。DirectML 实际防火墙下的 GUI、取消恢复与重整验收尚在进行。
- 两平台构建记录中的全部 **33 项生产源码**和 **39 项阅读器及对应源码资源**与冻结源文件一致。GPU 运行包继续使用此前已校验的固定版本，没有修改全局驱动或 CUDA Toolkit。
- 待完成：Windows 冻结 GUI 验收与产物格式检查、启动新版窗口、最终源码与发布附件交付。全新 Windows 系统、其他 Mac 系统版本与更多显卡型号仍未覆盖，不能把清洁 PATH 等同于全新系统。
