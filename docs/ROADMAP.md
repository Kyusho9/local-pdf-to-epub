# 已知限制和后续任务

## 发布阻塞

1. Windows干净系统：已生成x64发布包并在Windows 11实机通过GUI/CLI、VC++ DLL实际加载、取消恢复及真实防火墙阻断。现有主机装有开发工具且未启用虚拟化，仍需在全新Windows 10/11环境验收；不能把清除PATH等同全新系统。
2. Mac 发布信任：当前 arm64 包在本机运行并通过 ad-hoc 签名验证，未 Developer ID 签名/公证，最低声明 macOS 14，未覆盖 macOS 14–26 或其他 CPU。Intel 版待独立构建。
3. 可选 EPUBCheck 运行包：本次验收使用本地 Java 21 + EPUBCheck 5.4.0；主应用尚不含 Java/JAR。未来以单独许可齐备的本地校验运行包补齐。

## 内容质量范围

- 当前文字层可信判断是启发式。字形正常但语义错误的隐藏层可能漏判；用户可强制 OCR。没有声称检测所有错误层。
- 自制 60 条片段全部匹配只证明这些样本，不是通用 OCR 准确率。0.1.6 针对倾斜扫描反馈增加了局部缓存复核与自制几何回归，仍没有代表性长篇书籍、低分辨率或重阴影扫描的质量基准；发布状态见本版记录。
- 目前仅识别简单横排、简单双栏和有线框表格。复杂扫描表格、图形残留区域检测和数学公式不保证完整；发现可疑情况保留区域图片并提示，但仍须核对原页。
- 不支持竖排、手写、文字绕图、复杂跨栏阅读顺序的可靠自动恢复。下一步应以新样本比较 Docling 本地布局模型，维持 CPU/Mac 路径，避免同时加入多套重模型。
- 0.1.4提供可选真实页边显示，需本地兼容阅读器；按阅读页起始正文来源映射。页边角色识别仍可能有误，未知边界会清空并报告；没有正文可定位的原页及极长页边文字尚需补充专项样本，不保证所有阅读器支持。0.1.6 对版面证据充分的跨页段落保守自动合并，其余由人工确认；不确定的断词不自动修复。
- 脚注按原页唯一 `[数字]` 标记与引用关联；已验证跨页合并段落中相同编号分别链接各自原页脚注。来源不可靠、同原页多个同编号或真正跨原页引用仍保留内容并提示，需要更强关联和人工界面。
- 目录按书签/标题生成，用户可改标题和级别；没有完整目录树拖拽编辑、任意块重排序或图片裁切编辑器。
- 0.1.6 识别到原首页封面图时保留原图；没有可用原封面时使用文字封面，暂不提供自选封面编辑。

## 体验与工程

- 首版单任务；没有批量队列。取消在页边界生效，可强制结束后台；当前页需要重新处理。
- 资源目录/高级样式设置尚无独立用户偏好持久化，重开任务可恢复任务数据；非默认资源目录可通过环境变量固定。
- 缺模型时 GUI 会明确提示；纯文字无模型路径主要通过 CLI 使用。
- 0.1.5 增加 Windows DirectML / NVIDIA CUDA，Windows 新任务默认 DirectML；AMD/Intel 实机、Mac Metal、多 GPU 选择及更广泛硬件仍待验证。没有线上增强、遥测、账号、模型训练、翻译和生成式补写。
- 尚无长文档内存/磁盘配额压力测试、磁盘断电恢复测试与恶意复杂 PDF 解析隔离强化。任务快照包含原文件和提取正文，应按普通本地文档管理。
- 资源 SHA-256 校验保证完整性；应用和资源包尚无发行者数字签名链。后续需对可信发布渠道、自动更新（用户主动）与平台签名另行设计。
