# 首版解析后端

后端接口集中在 `src/local_epub/backend.py`。中间数据使用 PDF 点单位、左上原点坐标；只有 OCR 行保留引擎真实返回的识别分数。合并段落的总体分数为空，逐行分数仍在原始结果中。文字层没有置信度时记录空值。

选择 pdfplumber 0.11.6 提取原生文字、位置、简单线框表格，PDFium 5.14.0 渲染原页，RapidOCR ONNX 1.4.4 的 PP-OCRv4 中文识别模型处理扫描区域。这个组合没有大型视觉语言模型，原生支持 CPU，并能在 Windows x64 与 macOS arm64 安装对应二进制轮子。实际目标系统验证仍以测试记录为准。

RapidOCR 以显式本地模型路径初始化，三个推理会话均检查实际 provider 必须为 CPUExecutionProvider；不使用 CUDA、DirectML、CoreML。识别字符表位于识别模型元数据内。模型检查失败会报出缺项，不下载或调用云服务。

## 自动处理原则

1. 对乱码、私用区字符、异常重复、过小字号、整页扫描只带少量文字等情况标记文字层不可信。正常文字层优先直接使用；图片区域可附加 OCR，并过滤与文字层重叠的 OCR 行。强制 OCR 完全替换页面文字提取结果。
2. 中文行内不人为插入空格；近邻、同栏、相近字号且上一行未结束句子的内容可合并为段落。保留每一行来源范围。英文断词连字符不擅自删除。
3. 双栏按可见几何间隔识别，先左后右，跨栏标题分隔水平区间；报告要求人工回查。复杂杂志版式、多栏、侧注仍需校对。
4. 疑似页眉、页脚、页码和脚注保留并标记。EPUB导出层仅对同页唯一的`[数字]`脚注和唯一引用建立往返链接；不满足条件的脚注保留内容并提示，避免误配引用。
5. 原生线框表格可生成单元格数据，合并单元格需要核对。位图和矢量图形按原区域截图保留。检测到等号、求和、积分等独立公式时，连同邻近上下标保留原区域图片，避免文字提取把上下标排错。混合页中的纯文字图片区域在 OCR 后改为正文，并保留原页回查。扫描页的非文字残留区域用图像启发式检测，不能保证覆盖所有公式、细线图表或低对比度插图。
6. OCR 没有检测到文字但页面可见内容并非空白时，记录页面失败而不是把空结果当作完成。纯图页需要用户回查后明确排除或保留为以后支持的图页，不会静默标记成功。

## 不能据此宣称的能力

0.1.1在完整文档组装阶段增加可恢复的页边内容识别（`margins.py`），不修改逐页提取结果。短单行必须位于顶部或底部6%区域，比同页正文文字区域小，在至少两页有相同位置和规范化后的相同文字；数字页码还要求与PDF页号有固定偏移。只规范Unicode兼容形式、空白及中点，不用模糊OCR相似度。缺坐标、标题、脚注、人工修订、正文参照不足等情况不自动隐藏。该规则可能漏掉其他样式页码，用户可在「正文处理」人工保留或排除；原始内容始终留在任务中。

首版不是完整书籍版式理解系统。它不保证识别语义正常但内容错误的隐藏文字层，用户可选择强制 OCR。中文竖排、手写、复杂公式转 MathML、复杂表格结构化以及复杂脚注引用尚未支持。扫描图像中的低对比度内容、OCR 未检测出的字块可能漏检，因此扫描页始终带原页复核提示。原始 PDF 快照、原始提取结果与人工修订分别保留，便于核对。

## 本阶段实测

已用当前机器 bundled PDF 运行时跑通两个原生样本共四页，检查中文、书签、双栏顺序、脚注、位图、矢量图、表格空值与公式截图；已检查无密码、错误密码、正确密码，以及禁止提取的用户密码和允许访问的所有者密码。随后已用项目固定依赖（pdfplumber 0.11.6、pypdfium2 5.14.0、RapidOCR 1.4.4、ONNX Runtime 1.20.1）新进程跑通全部三份自制 PDF 共八页。预期 text/ocr/mixed 路径均匹配；逐段真值比较忽略空白但保留标点，全部匹配且顺序正确。首次 OCR 初始化、错误文字层替换、混合页补充文字、原生表格空值、脚注及公式/矢量图原区域均验证。记录见 `artifacts/backend-acceptance.json`。这些小样本结果不构成对任意书籍的识别准确率承诺；离线系统约束与发布包测试见主测试记录。
